## 1. 任务目标

在现有 React/Vite 竖屏原型中实现可完整游玩的 R3 咖啡店垂直切片，替换原有“点击制作、自动进度、点击上菜”的单按钮营业方式。

实现完成后，玩家必须能够连续经历：

`准备 -> 开店 -> 顾客到店 -> 接单 -> 手工制作 -> 上菜 -> 清理 -> 打烊结算 -> 升级 -> 再开一天`

## 3. 实现范围

### 3.1 咖啡店入口

- 准备页合并原营业与经营入口。
- 显示今日目标、菜单、设备等级、宠物状态和开始营业按钮。
- 保留现有升级、研发和装饰购买能力。
- 打烊结算后回到准备页。

### 3.2 营业状态机

至少实现：

- `idle`
- `opening`
- `running`
- `closing`
- `settled`

顾客至少实现：

- `entering`
- `seated`
- `ordering`
- `waiting`
- `served`
- `satisfied`
- `impatient`
- `left`

桌位至少实现：

- 空桌
- 占座
- 有订单
- 已上菜
- 待清理

订单、设备、托盘、中间产物和事件必须通过动作函数修改，不允许散落布尔值拼接状态。

### 3.3 互动制作

必须实现：

- 接单。
- 原料拖拽到正确设备。
- 长按或滑动完成加工。
- 中间产物拖到装配台。
- 成品拖到托盘。
- 托盘拖到正确桌位。
- 空杯和桌面拖到清洗区。
- 错误放置可撤回。
- 拖拽之外提供点击或分步点击备选路径。

三种配方：

- 海盐拿铁：咖啡机、萃取、奶泡、组装。
- 黄油可颂：烤箱、批量或等待、装盘。
- 柑橘气泡水：加冰、注入、装饰。

每份订单应有 4 至 6 个有效动作，不得退化成一个“制作”按钮。

### 3.4 顾客、设备与节奏

- 四张桌和四类基础顾客。
- 顾客有耐心、偏好、订单、落座和离店状态。
- 咖啡机、烤箱、装配台、托盘、洗涤区可被占用。
- 90 至 180 秒标准营业时段。
- 每 20 至 30 秒至少安排一种小事件。
- 员工或玩家连续 8 秒无动作时提供准备、补货或清理入口。
- 订单失败只影响小费或评价，不阻断第二天。

### 3.5 经营回流

- 咖啡机、烤箱、吧台和招牌升级必须改变操作方式、容量或顾客结构，不能只改百分比。
- 完成结算后正确写入金币、经验、体力、顾客评价和营业记录。
- 升级消耗与现有经济兼容。

### 3.6 宠物与恋爱回流

- 布丁至少参与一次营业协助，如提醒耐心、递送物品或提高一次小费。
- 至少一位恋爱角色到店、帮忙或触发一句与关系值相关的短对白。
- 事件不能打断操作流，不应使用阻塞式长弹窗终止营业。
- 刷新后宠物、关系、金币、经验和升级状态保持。

## 4. 技术约束

- 保持 React + TypeScript + Vite 现有技术栈。
- 保持竖屏女性向手绘水彩方向，灰盒和 CSS 动画可作为正式美术前的降级。
- 不修改根目录文档，不修改 `work/**`。
- 不添加依赖，除非现有包无法合理完成；新增依赖必须在交付说明中说明。
- 不使用运行时大模型接口。
- 所有核心逻辑应拆成可测试的纯函数或 reducer。
- 结算必须幂等。
- 营业中页面失焦、切页或点击离开时必须暂停或确认。
- 页面在 430 x 932 和 375 x 812 下不得横向溢出、文字裁切或组件遮挡。
- 可点击区域至少 44 x 44 逻辑像素。
- 拖拽时要阻止营业页面滚动，并处理指针取消。
