## 2. 顾客 `CAFE_CUSTOMERS: CustomerTypeDef[]`

```ts
interface CustomerTypeDef {
  id: 'officeWorker' | 'tourist' | 'catLover' | 'regular'  // 必填=是
  name: string                  // 必填=是
  icon: string                  // 占位图标名，必填=是
  patienceMs: number            // 等待耐心，必填=是，取值 20000–120000
  walkMs: number                // 进店走到桌位时间，必填=是，取值 800–4000
  moveSpeedPx: number           // 场景移动速度，必填=是，取值 40–200（px/s）
  preferencePool: OrderPreference['kind'][]  // 可能提出的偏好，必填=是
  satisfactionBase: number      // 基础满意度（正确上菜即得），取值 0–100
  tipMin: number                // 小费下限（金币），取值 0–20
  tipMax: number                // 小费上限（金币），取值 0–30
  specialFeedback: string       // 特殊反馈文案，必填=是
  weight: number                // 出现权重，必填=是，取值 1–10
}
```

| id | name | icon | patienceMs | walkMs | moveSpeedPx | preferencePool | satisfactionBase | tipMin | tipMax | specialFeedback | weight |
|---|---|---|---:|---:|---:|---|---:|---:|---:|---|---:|
| `officeWorker` | 上班族 | `Briefcase` | 25000 | 1200 | 160 | `['lessSugar','extraShot']` | 70 | 3 | 8 | 「快速出餐的时候他会挑挑眉：效率不错。」 | 4 |
| `tourist` | 游客 | `Camera` | 60000 | 2600 | 70 | `['garnish']` | 85 | 2 | 12 | 「满意地举着杯子在店门口拍了张照。」 | 3 |
| `catLover` | 猫爱好者 | `Cat` | 40000 | 2000 | 90 | `['lessSugar','garnish']` | 80 | 4 | 10 | 「结账时多看了一眼趴在吧台上的布丁。」 | 2 |

## 4. 设备 `CAFE_DEVICES: CafeDeviceDef[]`

等级字段沿用 `GameState.equipment` 的 key（`machine/oven/counter/signboard`），费用公式沿用现有 `equipmentCost(id, level) = baseCost × costGrowth^(level-1)`，不改 `content.ts` 现有数值，只把「效果」落成玩法字段。

```ts
interface CafeDeviceDef {
  equipmentKey: 'machine' | 'oven' | 'counter' | 'signboard'  // 必填=是
  deviceKey: DeviceId | 'tray' | null   // 营业页对应设备，必填=是
  name: string                          // 必填=是
  icon: string                          // 必填=是
  baseCost: number                      // 必填=是（与 content.ts EQUIPMENT 一致）
  costGrowth: number                    // 必填=是（同上）
  maxLevel: number                      // 必填=是（同上）
  unlockLevel: number                   // 店铺等级解锁门槛，取值 1–10
  levels: CafeDeviceLevelDef[]          // 下标 = 等级-1，必填=是，长度 = maxLevel
}

interface CafeDeviceLevelDef {
  slots: number              // 并行槽位，取值 1–2
  durationMult: number       // 长按时长倍率，取值 0.5–1.0
  trayCapacity: number       // 仅 tray 类设备有效，取值 1–2
  operationChange: string    // 中文：这一级改变了什么操作方式，必填=是
}
```

### 4.1 咖啡机（equipmentKey: `machine`）

| 等级 | 费用（按公式） | slots | durationMult | operationChange |
|---|---:|---:|---:|---|
| Lv1 | 120 | 1 | 1.0 | 基础：单杯手压萃取 |
| Lv2 | 210 | 1 | 1.0 | 萃取容差放宽到 ±350ms，失误更少 |
| Lv3 | 368 | 2 | 1.0 | 解锁双杯并行：一次长按同时做两杯 |
| Lv4 | 644 | 2 | 1.0 | 萃取改为 2 连点替代手势（连点 2 次） |
| Lv5 | 1127 | 2 | 0.8 | 自动出杯：萃取完自动入托盘，省 1 次拖拽 |

### 4.2 烤箱（equipmentKey: `oven`）

| 等级 | 费用 | slots | durationMult | operationChange |
|---|---:|---:|---:|---|
| Lv1 | 100 | 1 | 1.0 | 基础：单批长按烘焙 |
| Lv2 | 170 | 1 | 0.9 | 烘焙时间缩短（1500→1350ms） |
| Lv3 | 289 | 2 | 0.9 | 双批同烤：一炉出两个可颂 |
| Lv4 | 491 | 2 | 0.8 | 烘焙时间再缩短（→1200ms） |

### 4.3 吧台 / 托盘（equipmentKey: `counter`，deviceKey: `tray`）

### 4.4 招牌（equipmentKey: `signboard`，deviceKey: `null`，无营业内操作）

## 5. 事件 `CAFE_EVENTS: EventDef[]`

```ts
interface EventDef {
  id: string                    // 必填=是
  category: 'customer' | 'device' | 'pet' | 'character'  // 必填=是
  weight: number                // 类内权重，取值 1–10，必填=是
  triggerCondition: string      // 可执行条件表达式描述（见各表），必填=是
  cooldownMs: number            // 同 id 冷却，取值 30000–120000
  pauseMs: number               // 触发时冻结计时毫秒，0 = 不暂停
  durationMs: number            // 事件展示时长，必填=是
  effect: string                // 效果说明（程序字段见备注列），必填=是
  message: string               // 横幅文案，必填=是
}
```

## 7. 今日目标（准备页）`CAFE_DAILY_GOALS`

| id | name | 条件（每会话判定） | 奖励 |
|---|---|---|---|
| `goalServe6` | 上菜 6 单 | `stats.ordersServed >= 6` | +20 金币 |
| `goalNoTimeout` | 没让客人等走 | `stats.ordersTimeout === 0` | +15 金币 |
| `goalCleanAll` | 桌桌清爽 | closing 结束时无 dirty 桌 | +10 金币 |

以上奖励在 `settled` 时随结算一次性发放（幂等由 `settled` 标志保障）。
