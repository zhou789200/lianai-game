## 1. 范围与原则

- 只验证真实营业流程、边界状态与双视口体验，不只检查页面能打开。
- 本任务不修改 `app/src/**`。发现问题记录复现步骤、截图与源码位置，交 R3-02 / 主线修复。
- 每条用例输出稳定编号（下文 `TC-*`），并映射到 `work/r3/R3验收清单.md` 的 `R3-*` 用例。
- 涉及时间的用例使用语义等待（等待具体 DOM 状态 / 存档字段变化），禁止无语义超长 sleep。
- 未执行 / 依赖不存在的功能时，状态写 `未执行` 或 `阻塞`，不编造通过。

### 2.3 手势模拟方式

- 拖拽：`mouse.down()` 于原料中心 → `mouse.move()` 到目标 `[data-drop]` 中心 → `mouse.up()`（实现用 `elementFromPoint+closest('[data-drop]')` 判定落点，BusinessView.tsx:214-239）。
- 长按：`mouse.down()` 停留 `durationMs + 400ms` 后 `mouse.up()`。
- 滑动：`mouse.down()` 后横向 `mouse.move()` ≥130px 再 `mouse.up()`。
- 点击备选：普通 `click()`；加工步连点 3 次（每次 +34%，ProcessControl onClick 分支，BusinessView.tsx:772-784）。

## 5. 已知实现与规格差异（测试前代码走读结论，供报告核对）

1. RECOV-02 规格要求「超差提示 + 重做/采用二选一」；实现是松手即取消（PROCESS_CANCEL）并可直接重做，无「直接采用（满意度 -20）」分支。
2. RECOV-03 规格要求「3s 内取回无惩罚 / 超时满意度 -30」；实现是上错桌仅提示、不消耗成品，无取回窗口机制。
3. RECOV-07 规格要求「刷新后已完成单的金币/经验/统计保留」；实现是营业收益统一在 settle 时入账，营业中刷新即丢弃会话收益（体力会归还）。
4. FUNC-16 规格要求「暂停类事件冻结倒计时」；实现的事件均为氛围事件，无暂停类事件。
5. RECOV-09（切页防后台计时）：实现直接隐藏底部导航禁止切页，行为等效但路径不同。

以上差异在报告中按「规格偏差」列出，级别由影响评定；不作为脚本通过条件，脚本按实际实现断言。
