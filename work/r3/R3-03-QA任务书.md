# R3-03 QA 与体验验证任务书

任务编号：R3-03  
任务名称：R3 互动营业测试与验收  
责任角色：WorkBuddy / QA  
依赖：R3-02 首个可运行版本  
状态：待执行  
文件权限：只允许修改 `work/r3/**`、`work/shots/r3-*.mjs`

## 1. 任务目标

为 R3 互动营业建立可复现的测试计划、自动化脚本和验收报告，验证真实营业流程、边界状态和双视口体验，而不是只检查页面是否能够打开。

本任务不得修改 `app/src/**`。发现问题时记录复现步骤、截图和源码位置，由 R3-02 或主线修复。

## 2. 启动策略

可以立即开始：

- 阅读 R3 执行计划和 R3 测试验收要求。
- 建立测试计划、测试数据、选择器和脚本骨架。
- 设计 430 x 932、375 x 812 的截图与断言。

必须在 R3-02 对应功能存在后执行：

- 开始营业、制作、上菜、清理、结算。
- 刷新恢复、重复结算和体力校验。
- 宠物协助和角色事件的验收。

若实现尚未落地，产物报告状态写为 `WAITING_R3-02`。不得编造通过结果，也不得把未执行项写成通过。

## 4. 测试计划

至少覆盖以下场景：

### 4.1 主流程

- 准备页进入营业。
- 顾客进店、落座和生成订单。
- 接单、取料、长按、组装、上菜和清理。
- 三种配方各完成至少一份。
- 打烊结算、回到准备页、升级设备并再次开店。

### 4.2 互动恢复

- 把原料拖到错误设备。
- 中途取消拖拽。
- 点击备选路径完成同一订单。
- 订单等待过久、顾客不耐烦或离店。
- 暂停、继续、离店确认和取消离店。

### 4.3 结算与存档

- 重复点击打烊不会重复发奖。
- 结算后刷新，金币、经验、设备、宠物和关系状态正确。
- 营业中刷新或关闭页面不重复扣体力。
- 体力不足不能开始营业。
- 升级后下一次营业的效果发生变化。

### 4.4 回流

- 布丁至少触发一次实际营业协助。
- 恋爱角色至少触发一次到店、帮助或短对白事件。
- 事件结束后营业仍可继续，不卡死计时。

### 4.5 双视口

- 430 x 932。
- 375 x 812。
- 检查横向溢出、文字裁切、按钮遮挡、拖拽目标和固定区域重叠。
- 检查营业中浏览器失焦后计时与操作状态。

## 5. 自动化要求

- 使用仓库现有 Playwright 或浏览器脚本方式，不引入不必要的测试框架。
- 每项断言输出稳定的用例编号。
- 失败时保存截图、当前 URL、可见文本和控制台错误。
- 脚本可以在已启动的本地开发服务器上重复运行。
- 不依赖真实用户、网络服务或外部账号。
- 涉及时间的用例使用可控等待，禁止依赖无语义的超长睡眠。

## 6. 验收报告

报告必须包含：

- 测试版本和启动命令。
- 每条用例的状态：通过、失败、阻塞、未执行。
- 复现步骤和预期结果。
- 截图路径和控制台错误。
- 430 x 932、375 x 812 的布局结论。
- 阻断级、严重级、一般级问题清单。
- 与 R3 验收清单的逐项映射。
- 明确说明哪些结论来自自动化，哪些来自人工体验。

## 7. 完成标准

- 三份文档和两份 R3 脚本齐备。
- 主流程、恢复、结算、宠物、恋爱和双视口均有用例。
- 所有已执行用例有可复查证据。
- 未执行项明确标记，不以推测代替结果。
- 没有修改 `app/src/**`。

## 8. 汇报格式

- 产物路径。
- 执行命令与结果。
- 通过、失败、阻塞数量。
- 阻断问题与复现入口。
- 是否需要 R3-02 修复或主线合并。
