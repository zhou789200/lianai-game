## 2. 问题清单

### 阻断级（P0，必须修复才能过 R3）

**BUG-R3-P0-01：指针拖放完全不生效（拖拽主路径为死代码）**

- 复现步骤：开店 → 接单 → 按住任一原料（ghost 正常跟随）→ 拖到目标设备上松手。
- 预期：原料吸附设备、步骤推进（FUNC-05）或错误提示（RECOV-01）。
- 实际：无任何反应，步骤不变、无 toast；拖托盘到桌、空杯拖清洗区同样失效。
- 根因：`app/src/views/BusinessView.tsx` `onUp`（约 217-226 行）在调用 `applyDropRef.current(...)` **之前**执行 `dragRef.current = null`；而 `applyDrop`（约 164-168 行）开头重新读取 `dragRef.current`，恒为 null 直接 return。修复方向：`onUp` 将 payload 直接传给 `applyDrop`，或延后清空。
- 影响：R3-FUNC-05/09/11/13、RECOV-01/03、UI-06 的拖拽路径全部不可用；点击备选路径完整可用，玩法不致死锁，故按「单缺陷多用例阻塞」记录。
- 复现入口：营业页任意一次原料拖拽；自动化复现：`node work/shots/r3-edge-check.mjs` 的 TC-DRAG-PROBE。

### 严重级（P1，R3 结束前修复/对齐规格）

1. **D3｜营业中刷新丢弃已得收益**（RECOV-07）：规格要求已完成订单的金币/经验/统计在刷新后保留；实现将全部收益延迟到 settle 入账，`reconcileAbandonedRun` 只归还体力（storage.ts:163-171）。复现：营业中上菜 1 单后刷新，coins 不变。证据：TC-E07。
2. **D1｜长按超差无「直接采用」补救分支**（RECOV-02）：实现只有「取消重做」；规格的「直接采用（满意度 -20 继续链条）」不存在。BusinessView.tsx ProcessControl.onPointerUp。
3. **D2｜上错桌无取回/惩罚机制**（RECOV-03）：实现仅提示不消耗，无 3s 取回窗口与超时 -30 满意度。（修复 P0-01 后此路径才可实际触达。）

### 一般级（P2，登记后可延期）

4. **D4｜无暂停类事件**（FUNC-16）：事件全部为氛围类，「暂停类事件冻结倒计时」无从验证。
5. **D5｜RECOV-09 以禁止切页替代**：营业页独占视图、导航隐藏，行为等效但与规格路径不同。
6. **D6｜EVIDENCE-06 缺状态机单元测试**：R3-02 未交付 cafeSession 测试，reducer 分支覆盖只能靠 UI 脚本。
7. **D7｜拖拽 ghost 偶发未观测到**：一次运行中 TC-F05 的 ghost 计数为 false（另一次为 true），疑似与按住时长/渲染时机有关，修复 P0-01 后一并复测 UI-06（拿起/跟随/高亮三反馈 ≤100ms）。
